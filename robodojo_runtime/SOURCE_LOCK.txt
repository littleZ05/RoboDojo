Vendored paths: env/ src/ task/ utils/ env_cfg/ scripts/

The vendored tree is the tree this integration was validated against, not a
pristine upstream copy. Upstream's public release is eval-only: it ships
src/eval_client/ and no steppable environment client at all. There are three
deliberate differences and no others; they are itemised below.

--------------------------------------------------------------------------
1. Environment patch -- robodojo_runtime/PATCHES/environment.patch
--------------------------------------------------------------------------
sha256:   fa5f6219bb36cb1fdf957a63fbc326bbec5bff786f90185efb78ae6d919806a0
Applies to env/, src/ and task/RoboDojo/tasks/: cuRobo planner, robot / scene /
seed managers, the eval client, one task, and the eval script.
Why:      without it the wrapped environment does not reproduce the behaviour
          the recipes and the official success cases were validated against.
Note:     this patch is generated from the integration checkout, so it is the
          exact delta rather than a replayed snapshot. XPolicyLab (a submodule
          pointer) is excluded: the runtime does not vendor XPolicyLab.

--------------------------------------------------------------------------
2. Collection client -- new files, not present upstream
--------------------------------------------------------------------------
src/collect_client/__init__.py
src/collect_client/collect_env.py      steppable env built on RoboDojo's own
                                       ObsManager / SeedManager
src/collect_client/main.py             CLI entry point
src/eval_client/traj_recorder.py       trajectory + per-camera video recorder
                                       used by the environment server
Why:      RLinf's RoboDojoEnv and RPent's environment server both need to
          reset, step and record a RoboDojo environment. Upstream only ships
          the scripted eval client, so this is the missing half of the
          contract.
Provenance: written for the RLinf/RPent integration; MIT-compatible derivative
          work of RoboDojo. One machine-specific example path in main.py's
          docstring was replaced with /path/to/collect_result.

--------------------------------------------------------------------------
3. Code-root / data-root split -- env/global_configs.py
--------------------------------------------------------------------------
  ROOT_DIR     = os.environ.get("ROBODOJO_ROOT") or os.path.join(current_dir, "..")
  ASSETS_ROOT  = os.environ.get("ROBODOJO_ASSETS_ROOT") or ROOT_DIR
  ASSETS_PATH  = os.path.join(ASSETS_ROOT, "Assets")
  OBJECTS_PATH = os.path.join(ASSETS_ROOT, f"Assets/Object/{BENCHMARK}")
  ROBOTS_PATH  = os.path.join(ASSETS_ROOT, "Assets/Robots")
  ENV_CONFIG_PATH = os.path.join(ROOT_DIR, "env_cfg")

Why:      a wheel cannot carry a multi-gigabyte Assets/ tree, and RoboDojo
          derives both the code root and the data root from the location of
          env/. Splitting them lets the code ship as a distribution while the
          scene data stays on its own volume. With neither variable set the
          values are byte-for-byte upstream's.
